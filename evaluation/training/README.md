# Controlled from-scratch comparison

This experiment compares **RAC-1x**, **SSDD-S-F8C4**, and **DiTo-B-F8C4**. It is separate from the
official-checkpoint benchmark because the two experiments answer different questions.

## Fixed protocol

- Data: the shared local 100-class image set at 256 px, with the same files, split, transforms,
  sampled order, and augmentation seed for every method.
- Validation: the fixed evaluation view generated by `prepare_dataset_view.py`.
- Latent interface: continuous `4 x 32 x 32` (F8C4).
- Optimizer, schedule, precision, global batch size, and augmentation are matched whenever the
  architecture permits it. Method-specific losses remain unchanged.
- Save at fixed **images-seen** milestones. Also log training FLOPs and GPU-hours.
- Select checkpoints by validation rFID, never by the training loss.
- Report both fixed-data-budget and converged/best-validation results.

## What can and cannot be compared

Raw loss values are recorded for debugging, but are **not ranked across methods**: RAC, SSDD, and
DiTo optimize different objectives and their numerical scales are not commensurate. Shared curves
use validation rFID, PSNR, SSIM, LPIPS, throughput, GPU-hours, and images seen.

Create the non-copying dataset view with:

```bash
python evaluation/training/prepare_dataset_view.py
```

The generated manifest records the exact sources, counts, hashes, and split. The current view uses
1,340 training images from `mini-imagenet-100class-new` and the fixed evaluation inputs, with no
content-hash overlap between them.

## Capacity control

RAC-1x has about 49.5M unique parameters because encoding and decoding share one field. The native
SSDD-S-F8C4 checkpoint has 48.22M total parameters, while the controlled SSDD-S decoder attached
to the same frozen SD-VAE latent has 13.4M trainable decoder parameters. These are distinct
comparisons and must be labeled accordingly. DiTo-B is a stronger, larger reference; parameter
count and compute are shown explicitly rather than described as capacity matched.

## Reproducibility notes

- SSDD's current FP16 loop clips the autoencoder and auxiliary-loss parameters in two calls, which
  makes recent Accelerate versions unscale the same optimizer twice. Apply
  `patches/ssdd_single_grad_clip.patch` inside the SSDD checkout; it concatenates the trainable
  parameters and preserves the official clipping threshold in one call.
- Apply `patches/rac_seed_log_dir.patch` to the RAC trainer to expose deterministic output paths,
  optional gradient clipping, and explicit learning-rate override on resume. The controlled RAC
  run uses gradient-norm clipping at 1.0 after an unclipped pilot became numerically unstable.
- `dito_b_f8c4_local_smoke.yaml` is a one-update DiTo-B configuration for checking the complete
  local-data training path. Formal runs should override the four iteration fields with the shared
  budget and validation milestones.

## Stage 1: three shared passes

The first checkpoint uses batch size 2 and exactly 2,010 optimizer updates for every method. This
equals 4,020 images seen, or three complete passes over the 1,340-image training view. It is an
early-training comparison; extend all three runs together after inspecting their shared validation
curves.

RAC-1x (randomly initialized full decoder, frozen SD-VAE teacher):

```bash
CUDA_VISIBLE_DEVICES=5 python \
  /research/cbim/vast/sf895/code/Rectified-Auto-Coder/train_REPA_rac_tuning.py \
  --dataset evaluation/data/controlled-mini-imagenet/train \
  --teacher-pretrained stabilityai/sd-vae-ft-mse \
  --log-dir evaluation/results/training/rac/local_stage1 \
  --seed 0 --batch-size 2 --steps 2010 --sample-steps 4 \
  --grad-clip 1.0 --no-finetune-decoder --no-adapter --amp
```

SSDD-S with the same frozen SD-VAE latent:

```bash
CUDA_VISIBLE_DEVICES=6 python -m accelerate.commands.accelerate_cli launch --num_processes 1 \
  evaluation/third_party/SSDD/ssdd/main.py \
  run_name=local_stage1/ssdd_s_sdvae \
  ckpt_dir=$PWD/evaluation/results/training/ssdd \
  dataset.imagenet_root=$PWD/evaluation/data/controlled-mini-imagenet \
  dataset.im_size=256 dataset.batch_size=2 \
  ssdd.encoder=sdvae ssdd.encoder_train=false ssdd.decoder=S ssdd.compile=false \
  training.epochs=3 training.eval_freq=3 training.log_freq=50 \
  training.grad_clip=0.1 training.mixed_precision=fp16
```

DiTo-B-F8C4 (native jointly trained encoder and renderer):

```bash
cd evaluation/third_party/dito
CUDA_VISIBLE_DEVICES=7 python -m torch.distributed.run --nproc-per-node=1 run.py \
  --config ../../training/dito_b_f8c4_local_stage1.yaml \
  --name local_stage1_dito_b --save-root ../../results/training/dito --force-replace
```

## Required logging schema

Each checkpoint evaluation writes one JSON line with:

`method, run_id, seed, images_seen, optimizer_steps, train_loss_native, val_rfid, val_psnr,
val_ssim, val_lpips, train_flops, gpu_hours, parameters, encode_nfe, decode_nfe`.

Do not claim a win from a checkpoint that has not reached a validation plateau. If RAC trails, first
separate optimization progress from architecture by comparing fixed-budget and converged curves.
